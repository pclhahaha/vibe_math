〇、直觉入门——一个具体 λ 表达式，一步一步归约给你看

先看一个可以亲手验算的问题。在一个"函数不能给自己起名字"的世界里，怎么表示数字、怎么让函数反复呼唤自己？我们先用 λ 演算（lambda calculus）把"数字 2"写出来，再一步一步做归约，让你亲眼看见计算发生。

那"没有名字的递归"是什么？假设想定义阶乘。正常写法是 fact(n) = 若 n=0 则 1 否则 n·fact(n−1)——但这句话里 fact 用了自己的名字，而在 λ 演算里函数不能指着自己叫名字。1930 年代，数学家 Haskell Curry 发现一个神奇的公式 Y：它能把"递归的骨架"变成真正会递归的函数，而它自己完全没有名字、只有一个固定的形状。它就是本课的主角 Y 组合子。

洞察：没有名字、没有循环，照样能"自我呼唤"——Y 组合子证明递归是最根本的计算能力之一。只想懂核心思想，看到这里就够了。

〇·一、λ 演算的三件家具——变量、抽象、应用（直觉）

先抛开"递归"，把 λ 演算本身讲清楚。它的语法只有三种构造，闭着眼睛都数得完：

① 变量（variable）：x、y、f…，一个符号，代表"某个未知的输入"。它没有值，等具体代入时才知道是什么。

② 抽象（abstraction）：λx. M，读作"一个以 x 为参数的函数，它的身体是 M"。这是唯一的"造函数"手段。比如 λx. x 就是恒等函数（输入什么返回什么），λx. (x x) 是"把输入用在自己身上"的怪函数。

③ 应用（application）：M N，读作"把函数 M 用到参数 N 上"。比如 (λx. x) y 就是把恒等函数应用到 y。

规则也只有一条（外加两条"保险"规则，见〇·二）：β 归约——凡遇到 (λx.M) N 的形状，就整体替换成"把 M 里出现的每个 x 换成 N"。用箭头记作

为什么这么简单的东西也叫"计算"？因为替换本身就是机械的：给定一个项，按规则从左到右归约，归约到不能再归约（范式）就"算完了"。Church 在 1936 年证明了这套符号替换规则能做到一切图灵机做的计算——这是"计算不需要变量赋值、不需要循环"的最早版本。

举个立刻能验算的例子：(λx.x)(λy.y)，把恒等函数作用到恒等函数上 → 替换 x 为 λy.y，得 λy.y。再如 (λx.x x)(λx.x x)：把 x x 里的 x 换成 λx.x x，得到 (λx.x x)(λx.x x)——它归约成自己！这是"永远算不完"的第一个例子，我们后面还会见到它。

λ 演算只有三种语法（变量、抽象、应用）和一条规则（β 归约：遇到 (λx.M)N 就把 M 里的 x 换成 N）。替换就是计算。能归约到范式 = 算出了答案。

〇·二、三条铁律——α 等价、β 归约、η 归约（从直觉到严格）

为了让"替换"不产生歧义，λ 演算需要三条精确规则。前两条保证替换可靠，第三条让系统更整洁。

① α 等价（α-conversion）：改名的自由。λx. x 和 λy. y 是同一个函数——"绑定变量叫什么名字无所谓"。把函数体内受 λ 绑定的变量统一改名，得到的项同构等价。这条规则防止了"λx.λy. x 和 λy.λx. y"被误判为同一个（前者第一个参数、后者第二个参数）。

② β 归约（β-reduction）：真正的计算。就是〇·一那条：

"避开冲突"很重要：归约 (λx.λy.x) y 时，若直接把 x 换成 y，会得到 λy.y，把原来的外层 y 错当成绑定变量了。正确做法是先把 λy.x 改名成 λz.x，再替换得 λz.y。所以 β 归约前常先做 α 改名——严格的定义必须把这一手写进去。

③ η 归约（η-reduction）：剥掉多余包装。λx. (f x) 就是 f 本身（一个"把 x 传给 f"的函数，等于 f）。当 f 里不出现 x 时，λx. f x 可以化简成 f。这条规则对应函数外延性：两个函数对所有输入给出相同输出，就是同一个函数。

归约的顺序值得规范。一个项里往往有多个可归约的子项。正规顺序（normal order）先归约最外层、最左边的那个，它保证"只要范式存在，一定能归约到"（Church–Rosser 定理：归约顺序虽然不同，但范式唯一）。后面算阶乘时我们会遵守它。

三条铁律：α 改名（绑定变量可换名）、β 归约（把参数替换进函数体，是计算本身）、η 归约（λx.f x = f）。正规顺序归约 + Church–Rosser 保证"答案唯一且找得到"。

二、完整例题 2：阶乘的"递归骨架"——为什么函数需要 Y

现在设一个真正"想要自己呼唤自己"的问题：阶乘。目标：写出一个 λ 项 FACT，使得 FACT n 归约到 n!。先看"有名字"的版本长什么样，再把它改造成 λ 演算能接受的样子。

递归 = 找不动点。把"自己"改造成一个额外参数 f，得到骨架 FACTSTEP；只要有一个满足 Y g = g (Y g) 的操作 Y，F = Y FACTSTEP 就是真正的阶乘。剩下的问题只有一个：Y 长什么样？

五、Turing 完备性——λ 演算 = 图灵机

Y 组合子解决的不只是"好看"：它把递归加进了 λ 演算，从而补上了 λ 演算成为通用计算模型最后一块拼图。

1936 年，两个年轻人几乎同时、从完全不同的方向定义了"可计算"：Alonzo Church 的 λ 演算和 Alan Turing 的图灵机。之后证明它们是等价的——两个系统定义的是同一个可计算函数类。等价的关键桥梁正是 Y：

图灵机的"循环"（状态会反复用到同一行表）对应 λ 演算的"递归"（Y 反复展开同一个骨架）。没有 Y 的 λ 演算只能写"一定终止"的程序，表达能力残缺；有了 Y，任何能用循环/递归写出的算法都能翻译成 λ 项。

由此得到本课最重要的结论之一：

λ 演算 = 图灵机 = 递归函数（Church 1936 / Turing 1936）。三种完全不同的形式系统定义了完全相同的"可计算"类。Y 组合子正是把"递归"这个能力焊进 λ 演算的那个焊点。

既然等价，为什么还要学 λ 演算？因为它是函数式编程的语言理论内核，也是证明助手类型理论的基石（见第七节）——它把"程序"表现为可读、可代数操作的表达式，而不是难以分析的状态转移表。

七、Curry-Howard 同构——类型即命题

本课最深刻的结果出现在逻辑与计算的交界：程序就是证明。

Curry（1934）和 Howard（1969）发现，λ 演算和自然演绎证明之间有一个逐条对应的字典：

类型（type）= 命题（proposition）：一个类型 A 就是一条断言 A。

程序（term）= 证明（proof）：一个类型为 A 的 λ 项，就是 A 的一个证明。

β 归约 = 切消（cut-elimination）/证明正规化：程序的执行（归约）对应证明中"绕弯子引理"的消除。同一个数学结构，在计算这边叫"运行"，在逻辑这边叫"化简证明"。

逐条验证：函数类型 A → B 就是蕴含 A ⟹ B；"给一个 A 得到 B"的程序就是"假设 A 推出 B"的证明。类型 (A×B) → A 的项 λp. (左分量 p)，正是证明 A∧B ⟹ A 的证明。你的每一个类型正确的程序，都在不动声色地证明一条定理。

Y 在逻辑里的名字。Y 的类型是 (A → A) → A（因为 Y 把"骨架"变成不动点）。把它当命题读：(A ⟹ A) ⟹ A。这不是一个普遍成立的逻辑公式（仅当 A 恒真时成立）——正是这个"例外"透露了 Y 的本质：Y 对应的是数学归纳法/递归原理，而归纳原理在自然数上恰好是真的。于是 Y 组合子 = 数学归纳法，两个看似无关的概念是同一个东西的两张脸。

为什么这件事改变世界？因为"证明 = 程序"意味着：写一个类型正确的程序，就等于写了一个证明，而且类型检查器会自动验证证明。Coq、Lean、Agda 等证明助手就建立在这个原理上——你把要证的定理声明成类型，把证明写成程序，类型检查就是证明验证。2019 年 Lean 的数学库就是靠这台"程序-证明"机器管理着几十万条定理。

Curry-Howard 同构：证明 = 程序、命题 = 类型、切消 = β-归约。Y 组合子 = 数学归纳法。Coq / Lean / Agda 的核心机制就是类型检查 = 证明验证。

八、函数式编程的根基——递归是循环的语法糖

Y 不只是理论玩具：它是函数式编程语言里递归的最终解释。

Haskell、Lisp、Scheme 等语言的递归机制，在理论上都可以追溯到 Y 组合子——"函数能调用自己"在语言层面是内置的便利，但它的数学基础就是"Y 提供了不动点"这一事实。纯函数式语言没有 while 循环；所有的重复（遍历、累加、迭代）都被写成递归，而递归能写出来，正是因为语言底层悄悄提供了类似 Y 的能力。

一个直接的推论。既然递归 = 不动点，那"计算不需要变量赋值"就成立：不需要先给 x 赋值再反复修改 x，用递归 + 参数传递就能完成一切循环。这也是函数式编程"不可变数据"风格的根基——没有赋值，就没有"状态被意外篡改"的 bug 类别。

实践上，现代语言不会让你手写 Y（太容易栈溢出），但概念完全同构：Haskell 里的 let f = ... in ... 自带不动点语义；Scheme 的 define 允许递归定义；Rust、OCaml 用代数数据类型 + 模式匹配把"递归数据结构"编码进类型系统。理解 Y，等于理解了这一切共用的同一个引擎。

Haskell / Lisp / Scheme 的递归在理论上都能追溯到 Y 组合子。纯函数式语言没有循环——所有循环都是递归的语法糖。递归 = 不动点，这就是"计算不需要变量赋值"的终极证明。

九、关键公式

十、工作题（带解答）

题 1（Church 算术：乘法）。给出 Church 数字的乘法函数 MULT = λm.λn.λf.λx. m (n f) x，并说明为什么它计算 m × n。

显示解答

把 m 作用到 (n f) 上：n f 是"把 f 作用 n 次的函数"，那么 m (n f) 是"把 (n f) 作用 m 次的函数"，即把 f 作用 n×m 次。于是 m (n f) x 把 x 经过 n×m 次 f，正是 Church 数字 m×n 的定义 λf.λx. f^{mn}(x)。∎

题 2（验证不动点恒等式）。对 g = λf.λx. f x，手动展开 Yg 的前两步，确认出现 g(Yg) 的形状。

显示解答

Yg → (λx.g(x x))(λx.g(x x)) → g((λx.g(x x))(λx.g(x x))) = g(Yg)。其中最后一步把圆括号里的项重新认出为 Yg。所以 Yg 归约到 g(Yg)，恒等式成立。∎

题 3（ω 为什么不终止）。证明 ω ω = (λx.x x)(λx.x x) 归约后还是自己，从而没有范式。

显示解答

ω ω → (x x)[x := ω] = ω ω。每一次归约都回到自身，永远到不了范式。这就是"永不终止的 λ 项"的最小例子，也是 Y 里自指的种子。∎

题 4（SKI 还原 I）。证明 SKK = I（即 S K K x 对任意 x 归约到 x）。

显示解答

S K K x → K x (K x)（用 S 的定义，x 先取 K、y 取 K、z 取 x）→ x（用 K 的定义丢掉第二个参数 K x）。所以 S K K 作用任何 x 都得 x，即 SKK = I。∎

题 5（Curry-Howard 的对应）。指出下面这个"程序"对应的逻辑公式：λx.λy. x（类型 A → B → A）。

显示解答

类型 A → B → A 读作命题 A ⟹ B ⟹ A，即 A ⟹ (B ⟹ A)。程序 λx.λy.x：给定 A（x）再给定 B（y），返回 x——这就是"在假设 B 的前提下仍可重申已成立的 A"，是直觉主义逻辑的公理之一（弱化规则）。类型正确的程序自动给出了这条命题的证明。∎

十一、试试看（带提示）

1. Church 数字的加法。写 ADD = λm.λn.λf.λx. m f (n f x)，验证 ADD 2 1 归约到 3。提示：先让 n f 产生"把 f 作用 n 次的函数"，再让 m f 套在它外面：m f (n f x) = 先把 f 作用 n 次、再作用 m 次，共 m+n 次。

2. 自己推 S 2 = 3。把〇·二到第一节的归约重写一遍，不看书：从 S 2 出发到 λf.λx.f(f(f x))。提示：只有两轮 β 归约；第二轮要把 λf.λx.f(f x) 先应用到 f（得 λx.f(f x)）再应用到 x（得 f(f x)）。

3. 用 Y 定义"无限循环"。设 LOOP = Y (λx. x)（骨架是恒等函数）。解释 LOOP 的归约行为。提示：Y(λx.x) → (λx.x)(Y(λx.x)) → Y(λx.x)——它归约回自己，永不停止，是"死循环"的最小程序。

4. 为什么 YF = F(YF) 里两边的 F 数量不一样，却仍然"恒等"？提示：这个"恒等式"是 β 归约意义下的（左边可归约到右边），不是语法上的完全相同；Y 的妙处正是把"少一层 F"的项展开成"多一层 F"。

5. 类型 (A → B) → A → B 对应哪条逻辑规则？提示：读作 (A ⟹ B) ⟹ A ⟹ B，即"从函数与参数推出结果"——这是蕴含的消去规则（modus ponens）。程序 λf.λx. f x 就是这条规则的证明。

6. 用正规顺序 vs 内层先归约，算 (λx.y)(ωω) 会有什么不同？提示：正规顺序先归约最外层：λx.y 直接吞掉参数 ωω，因为 x 没出现在函数体里，直接得 y，一步完成；内层先归约则会在 ωω 上永远打转。这就是"存在范式的项，正规顺序保证能找到"的含义。

前沿：程序语言设计中的不动点

现代函数式语言（Rust、Haskell、OCaml）把"不动点"从角落里的 Y 变成了类型系统的日常机制：通过代数数据类型（ADT）和模式匹配，递归数据结构（链表、树）与递归函数被编码进类型本身，编译器静态检查"每种情况都被处理"。Haskell 的 fix :: (a → a) → a 就是 Y 的静态类型版本（允许非终止，所以类型系统要睁一只眼闭一只眼）。仍开放的核心问题：线性类型系统中不动点的完整理论——在线性逻辑（如 Rust 的 borrow checker，资源只能使用一次）的约束下，如何在不违反所有权的前提下表达递归？线性类型严格限制"一个资源用一次"，而递归天然要求函数被反复调用，两者的调和目前只有部分方案（如"不可逆的代数数据类型"与 typed Racket 的实验），尚无统一理论。
